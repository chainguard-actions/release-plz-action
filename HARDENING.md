### script-injection (severity: high)

Sub-rule (a): the 'Install release-plz' step puts an input expression directly into the run script: `release-plz@${{ inputs.version }}\`. Fix: pass the input through an env var (e.g. RELEASE_PLZ_VERSION: ${{ inputs.version }}) and use it double-quoted: "release-plz@${RELEASE_PLZ_VERSION}".

### script-injection (severity: high)

Sub-rule (a): the 'Run release-plz' step puts many input expressions directly into the run script, including `if [[ -n "${{ inputs.config }}" ]]`, `echo "using config from '${{ inputs.config }}'"`, `TOKEN=("--token" "${{ inputs.token }}")`, `FORGE=("--forge" "${{ inputs.forge }}")`, `ALT_REGISTRY=("--registry" "${{ inputs.registry }}")`, `MANIFEST_PATH=("--manifest-path" "${{ inputs.manifest_path }}")`, and `if [[ -z "${{ inputs.command }}" || "${{ inputs.command }}" == "release-pr" ]]`. The inputs involved are config, verbose, dry_run, token, forge, backend, registry, manifest_path, project_manifest and command. All of them should go into the step's env: block and be referenced as double-quoted shell variables.
