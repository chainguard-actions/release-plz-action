## Findings Fixed

### script-injection (severity: high)

Sub-rule (a): the 'Install release-plz' step puts an expression straight into the run: script: `release-plz@${{ inputs.version }}\`. The caller controls inputs.version, and it is substituted into the shell script before bash runs it. Fix: move it to `env: RELEASE_PLZ_VERSION: ${{ inputs.version }}` and use `"release-plz@${RELEASE_PLZ_VERSION}"` in the script.

Locations:

- `action.yml:87`

### script-injection (severity: high)

Sub-rule (a): the 'Run release-plz' step puts many inputs.* expressions straight into the run: script, for example `if [[ -n "${{ inputs.config }}" ]]`, `CONFIG_PATH=("--config" "${{ inputs.config }}")`, `TOKEN=("--token" "${{ inputs.token }}")`, `FORGE=("--forge" "${{ inputs.forge }}")`, `ALT_REGISTRY=("--registry" "${{ inputs.registry }}")`, `MANIFEST_PATH=("--manifest-path" "${{ inputs.manifest_path }}")`, and `if [[ -z "${{ inputs.command }}" || "${{ inputs.command }}" == "release-pr" ]]`. The same applies to inputs.verbose, inputs.dry_run, inputs.backend and inputs.project_manifest. Each value is substituted into the script text, so a value containing a double quote or a $(...) runs shell commands. Fix: map each input to an env: variable and reference it in double quotes.
